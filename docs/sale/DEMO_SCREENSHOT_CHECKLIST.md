# AURELIA — Демо-скриншоты: набор и чек-лист (Demo Screenshots v1)

> **Назначение.** Закрывает пробел из этапа 32A: пакет продажи ссылался на
> скриншоты, которых не было. Здесь — **уже снятые** скриншоты витрины и **чек-лист
> ручной досъёмки** для интерактивных и админских экранов, которые нельзя снять
> простым «URL → скриншот».
>
> **Правила честности:** скриншоты не дорисовываются и не редактируются так, чтобы
> исказить продукт. Дизайн сайта не менялся. Только локальные демо-данные. Никаких
> секретов и реальных данных покупателей.

Папка ассетов: [`./screenshots/`](./screenshots/). Снято на локальном dev-сервере
(`http://127.0.0.1:5000`) через **Microsoft Edge headless** (`--screenshot`), без
установки новых зависимостей и без деплоя.

Как использовать скриншоты на показе и операционный порядок демо — в
[`DEMO_RUNBOOK.md`](./DEMO_RUNBOOK.md).

## 2. Нужно доснять вручную (интерактив — требует действий в браузере)

Эти экраны зависят от состояния корзины (`localStorage`), поэтому headless
«URL → скриншот» их не показывает. Снять **вручную** в обычном браузере на локальном
демо:

- [ ] **Корзина с выбранным вариантом** *(обязательно)* — добавить товар с вариантом,
      открыть корзину/дровер; видно отдельную строку с пометкой варианта.
      → `11-cart-variant-desktop.png`, `12-cart-variant-mobile.png`.
- [ ] **Чекаут с ручной оплатой и доставкой** *(обязательно)* — при непустой корзине
      открыть `/checkout`; видны опции доставки (Самовывоз/Новая Почта/Укрпочта/Курьер)
      и оплаты (при получении / по реквизитам).
      → `13-checkout-filled-desktop.png`, `14-checkout-filled-mobile.png`.
- [ ] **Инлайн-подтверждение заказа** *(опционально)* — оформить **тестовый** заказ
      на локальных демо-данных; видно подтверждение с номером `AUR-XXXXXXXX`.
      → `15-order-confirmation-desktop.png`. *(Только тестовые данные, без реальных PII.)*

## 3. Нужно доснять вручную (админка — требует авторизованной сессии)

Админ-маршруты отдают `307 → /admin/login` без сессии, поэтому headless снимает
только страницу входа. Войти **локально** под dev-учёткой (значения — из `.env.local`,
**на экране не показывать**) и снять:

- [ ] **Входящие заказы / дашборд** *(обязательно)* → `21-admin-orders-inbox.png`.
- [ ] **Каталог в админке** *(обязательно)* → `22-admin-catalog.png`.
- [ ] **Редактирование товара** (изображения/галерея/варианты/остаток) *(обязательно)*
      → `23-admin-product-edit.png`.
- [ ] **Карточка заказа** (вариант/оплата/доставка/жизненный цикл) *(обязательно)*
      → `24-admin-order-detail.png`.

> Перед админ-скриншотами создать **тестовый** заказ на демо-данных; не использовать
> реальные имена/телефоны/почту. После — тестовый заказ можно отменить (отмена
> возвращает остаток).

## 4. Правила и соглашения

**Чувствительные данные**
- Только локальные **демо-данные**; никаких реальных покупателей.
- **Никаких секретов** на скриншотах: поля логина/пароля пустые; не показывать
  `.env`/`.env.local`, токены, cookie, реквизиты.
- Тестовые заказы — с вымышленными контактами.

**Вьюпорты**
- Desktop: **1366 × 1000** (при необходимости выше для длинных страниц).
- Mobile: **390 × 844**; для страниц товара брать выше (например **390 × 1500**),
  чтобы в кадр попал селектор варианта и «Купить».

**Именование**
- `NN-<экран>-<desktop|mobile>.png`, нумерация по порядку демо-сценария
  (см. [`BUYER_DEMO_SCRIPT.md`](./BUYER_DEMO_SCRIPT.md)).

**Где хранить**
- Все файлы — в [`./screenshots/`](./screenshots/).

**Обязательные vs опциональные**
- Обязательные: §2 (корзина с вариантом, чекаут с оплатой/доставкой), §3 (все четыре
  админских экрана).
- Опциональные: §2 подтверждение заказа; дополнительные ракурсы/мобильные дубли.

**Как воспроизвести съёмку витрины** (для справки; без новых зависимостей)
1. `npm run db:start` → `npm run db:health` (БД на **6700**; dm-bot на 5432 не трогаем).
2. `npm run dev` → `http://127.0.0.1:5000`.
3. Edge headless, по одному снимку на запуск:
   `msedge --headless --disable-gpu --hide-scrollbars --window-size=1366,1000 --screenshot="<out>.png" "http://127.0.0.1:5000/<path>"`.
