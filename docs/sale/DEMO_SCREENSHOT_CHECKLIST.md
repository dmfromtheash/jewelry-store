# AURELIA — Демо-скриншоты: набор и чек-лист (Demo Screenshots v1)

> **Назначение.** Закрывает пробел из этапа 32A: пакет продажи ссылался на
> скриншоты, которых не было. Здесь — **уже снятые** скриншоты витрины и **чек-лист
> ручной досъёмки** для интерактивных и админских экранов, которые нельзя снять
> простым «URL → скриншот».
>
> **Правила честности:** скриншоты не дорисовываются и не редактируются так, чтобы
> исказить продукт. Дизайн сайта не менялся. Только локальные демо-данные. Никаких
> секретов и реальных данных покупателей.

Папка ассетов: [`./screenshots/`](./screenshots/). Снято на локальном dev-сервере
(`http://127.0.0.1:5000`), без установки новых зависимостей и без деплоя.
Статические страницы витрины (§1) сняты через **Microsoft Edge headless**
(`--screenshot`). **Интерактивные** (корзина/чекаут/подтверждение) и **админские**
(дашборд/каталог/редактор товара/карточка заказа) экраны сняты в **этапе 35B**
через **Edge + DevTools Protocol** (тот же уже установленный Edge, без новых
npm-зависимостей и без E2E-харнесса) — это позволило реально кликнуть «Купить»,
заполнить форму и войти в админку.

> **Статус набора (35B):** все обязательные интерактивные и админские скриншоты
> **сняты**. Это **локальные dev-снимки** (виден индикатор Next.js dev «N»), а не
> финальные production-маркетинговые ассеты.

Как использовать скриншоты на показе и операционный порядок демо — в
[`DEMO_RUNBOOK.md`](./DEMO_RUNBOOK.md).

## 4. Правила и соглашения

**Чувствительные данные**
- Только локальные **демо-данные**; никаких реальных покупателей.
- **Никаких секретов** на скриншотах: пароль/токены/cookie/реквизиты не показываются;
  не открывать `.env`/`.env.local`. На админских кадрах в шапке виден только
  логин-идентификатор `admin` (без пароля) — при передаче покупатель задаёт свои
  значения `ADMIN_*` в `.env.local`.
- Демо-заказы — с вымышленными контактами.

**Вьюпорты**
- Desktop: **1366 × 1000** (при необходимости выше для длинных страниц).
- Mobile: **390 × 844**; для страниц товара брать выше (например **390 × 1500**),
  чтобы в кадр попал селектор варианта и «Купить».

**Именование**
- Статика витрины (§1): `NN-<экран>-<desktop|mobile>.png` по порядку демо-сценария
  (см. [`BUYER_DEMO_SCRIPT.md`](./BUYER_DEMO_SCRIPT.md)).
- Интерактив/админка (§2–§3, 35B): описательные kebab-case имена
  (`cart-with-variant.png`, `filled-checkout.png`, `order-confirmation.png`,
  `admin-dashboard.png`, `admin-catalog.png`,
  `admin-product-edit-gallery-variants-stock.png`, `admin-order-detail.png`),
  с суффиксом `-mobile` для мобильных дублей.

**Где хранить**
- Все файлы — в [`./screenshots/`](./screenshots/).

**Обязательные vs опциональные — статус**
- Обязательные: §2 (корзина с вариантом, чекаут с оплатой/доставкой), §3 (все четыре
  админских экрана) — **сняты (35B)**.
- Опциональные: подтверждение заказа — **снято**; мобильные дубли корзины и
  чекаута — **сняты**. Остаётся опциональным: пересъёмка против production-сборки для
  «чистых» ассетов без индикатора «N».

**Дев-режим / честность ассетов**
- Это локальные dev-снимки; в углу виден индикатор Next.js dev «N» — артефакт
  dev-сборки, на проде его нет. Для финальных маркетинговых ассетов снимать против
  production-сборки или обрезать индикатор (без редактирования содержимого страницы).

**Как воспроизвести съёмку** (для справки; без новых зависимостей)
1. `npm run db:start` → `npm run db:health` (БД на **6700**; dm-bot на 5432 не трогаем).
2. `npm run dev` → `http://127.0.0.1:5000`.
3. Статика витрины (§1): Edge headless, по одному снимку на запуск:
   `msedge --headless --disable-gpu --hide-scrollbars --window-size=1366,1000 --screenshot="<out>.png" "http://127.0.0.1:5000/<path>"`.
4. Интерактив/админка (§2–§3): тот же Edge, запущенный с
   `--remote-debugging-port`, управляется через DevTools Protocol (встроенные в
   Node 22 `fetch`/`WebSocket`) — клик «Купить», заполнение формы, вход в админку,
   `Page.captureScreenshot`. **Новые npm-зависимости не ставились; E2E-харнесс в
   репозиторий не добавлялся** (управляющий скрипт — одноразовый, вне репозитория).
