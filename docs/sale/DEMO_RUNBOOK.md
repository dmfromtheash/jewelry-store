# AURELIA — Демо-раннбук (Demo Runbook v1)

> **Назначение.** Практический «день-икс» сценарий: как показать AURELIA
> потенциальному покупателю на текущей локальной/демо-сборке, опираясь на уже
> готовый пакет продажи и скриншоты. Закрывает пробел: скриншоты и пакет продажи
> есть, а пошагового операционного раннбука и заметки о готовности демо-URL не
> было.

## 1. Назначение

- **Как использовать проект на демо.** Показываете AURELIA локально (на своём
  компьютере) либо по скриншотам; покупатель видит готовую витрину + админку +
  сквозной поток заказа.
- **Что демонстрируем.** Каталог на БД, страницы товара с **вариантами** и
  галереей, гостевую корзину/оформление с **ручной** оплатой и доставкой,
  инлайн-подтверждение заказа, и админку: заказы, каталог, фото/галерею, варианты,
  остатки, жизненный цикл заказа.
- **Чего НЕ обещаем.** Это **sale-ready MVP** — *показуемый и адаптируемый*, а не
  *запущенный и принимающий деньги через провайдера*. Полный список ограничений —
  [`FEATURES_AND_LIMITS.md`](./FEATURES_AND_LIMITS.md) и §8 ниже.

## 2. Режимы демо

1. **Локальное демо (сейчас, основной режим).** Владелец/Claude запускает проект
   на `localhost` (`http://127.0.0.1:5000`) и показывает с экрана или шарит экран
   в видеозвонке. Ничего наружу не публикуется.
2. **Временный публичный демо-URL (опционально, в будущем — НЕ в этом этапе).**
   Возможность дать покупателю кликабельную ссылку. **Сейчас не создаётся**:
   ни туннель, ни хостинг в этом этапе не настраиваются. Требования — см. §6.
3. **Продакшн-хостинг (будущий этап, не сделан).** Полноценный деплой на домен —
   отдельный этап за чек-листом готовности и **явным согласием владельца**.

> **Важно:** живого размещённого демо сейчас НЕ существует. Не обещайте покупателю
> ссылку, пока §6 не выполнен осознанно владельцем.

## 3. Пред-демо чек-лист (только безопасные проверки)

- [ ] **Репозиторий чистый и синхронизирован.** `git status` — без правок; ветка
      `main` совпадает с origin. На демо не коммитим и не пушим.
- [ ] **БД AURELIA поднята на `localhost:6700`.** Проверка: `npm run db:status` и
      `npm run db:health` (ожидаем `HEALTH: OK`). Поднять при необходимости:
      `npm run db:start`.
- [ ] **dm-bot PostgreSQL на `:5432` НЕ трогаем** — это отдельная система, не имеет
      отношения к AURELIA (порт AURELIA — **6700**).
- [ ] **Витрина запущена.** `npm run dev` → `http://127.0.0.1:5000`.
- [ ] **Проверки готовности (локально, только чтение).** `npm run demo:rehearsal`
      (офлайн-гейт: preflight + typecheck + prisma validate + консистентность док-пакета);
      по желанию `npm run smoke:routes` и `npm run smoke:admin` при поднятых БД+сервере.
      **Без деплоя/туннеля; секреты не выводятся.**
- [ ] **Секреты не показываем.** Не открывать `.env` / `.env.local`, не выводить
      токены/пароли/cookie на экран; поля входа в админку оставлять пустыми до ввода.
- [ ] **Демо-данные санитизированы.** Только локальные демо-товары и **вымышленные**
      контакты в тестовых заказах; никаких реальных персональных данных покупателей.
- [ ] **Скриншоты под рукой.** Готовые ассеты — в
      [`screenshots/`](./screenshots/) (резервный показ, если что-то не запустится).

> Все упомянутые команды уже существуют в `package.json`
> (`db:start` / `db:status` / `db:health` / `db:stop` / `db:backup` / `dev`).
> **Не** придумывайте новых команд и **не** запускайте `reset` / `drop` / `seed`.

## 4. Демо-поток (10–15 минут)

Операционная версия [`BUYER_DEMO_SCRIPT.md`](./BUYER_DEMO_SCRIPT.md). Открыть лучше
и на ноутбуке, и на телефоне (первое впечатление — на телефоне).

**Часть «Покупатель» (≈ 6–8 мин)**
1. **Главная** `/` — витрина из PostgreSQL, категории, баннер-плейсхолдер.
2. **Категории** `/category/bijouterie`, `/category/gifts` — сетки товаров.
3. **Товар с вариантами** `/product/serogi-kaplya` — галерея, **селектор покрытия**
   (Позолота / Родирование / Сталь), цена в **₴**, влияние варианта на цену.
4. **Галерея** — миниатюры на странице товара.
5. **Добавление в корзину** — выбрать вариант → «Купить/В корзину»; в корзине
   строка помечена вариантом (идентичность `slug + variantId`).
6. **Товар без вариантов** `/product/sertifikat-podarochnyj` — добавляется как
   обычно. **Товар «Скоро»** `/product/kulon-gran` — без кнопки заказа и без цены.
7. **Оформление** `/checkout` — **ручная** модель: доставка (Самовывоз / Новая
   Почта / Укрпочта / Курьер) + свободное поле; оплата («при получении» /
   «по реквизитам»). Заполнить имя/телефон/город, оформить.
8. **Подтверждение** — инлайн-подтверждение с номером `AUR-XXXXXXXX`, корзина
   очищается.
8a. **Личный кабинет** `/account` (по желанию) — регистрация/вход, профиль
    (имя/телефон), **смена пароля**, и **история заказов + страница своего заказа**
    (виден только свой заказ). Подчеркнуть: **гостевое оформление сохранено**, аккаунт —
    это дополнение, а не замена.

**Часть «Админ / владелец» (≈ 4–6 мин)** — вход `/admin/login` (учётка из
`.env.local`, **на экран не выводить**).
9. **Дашборд / входящие заказы** `/admin/orders` — только что оформленный заказ в
   списке.
10. **Карточка заказа** — снимок позиций, выбранный **вариант**, способы
    **оплаты/доставки**, контакты, итог в ₴.
11. **Жизненный цикл** — провести `submitted → processing → completed` (или
    `cancelled`); переходы контролируются и пишутся в журнал. На **тестовом** заказе
    показать, что **отмена возвращает остаток**.
12. **Каталог** `/admin/catalog` — создание/редактирование товара,
    публикация/скрытие, **главное изображение + галерея**, **варианты** (добавить/
    изменить/удалить, «по умолчанию»), **остаток** на складе.
13. **Журнал аудита** `/admin/audit-log` — действия админа **и** события авторизации
    покупателя (`customer.*`: вход/регистрация/смена профиля/пароля, срабатывания
    лимита). Без секретов/PII — только тип события и id.

> **После демо:** остановить сервер (Ctrl+C) и `npm run db:stop`. Не оставлять
> поднятыми; ничего не публиковать, не коммитить, не пушить во время демо.

## 6. Готовность к демо-URL (что нужно ДО публичной ссылки)

Сейчас публичный URL **не создаётся**. Прежде чем делиться ссылкой, владелец должен
осознанно закрыть:

- [ ] **Решение о безопасном хостинге/туннеле** — где и как поднимается публичный
      доступ. *(В этом этапе ничего не настраивается; Cloudflare/VPS/туннель НЕ
      сконфигурированы и НЕ заявляются как готовые.)*
- [ ] **Переменные окружения** настроены владельцем в `.env.local` (по образцу
      `.env.example`) — **без секретов в репозитории и на экране**.
- [ ] **План продакшн-БД и бэкапов** — отдельная БД для публичного демо (не личная
      рабочая), регулярный бэкап (`npm run db:backup`), без реальных данных
      покупателей.
- [ ] **Админ-доступ обрабатывается приватно** — учётка не в коде, не в скриншотах,
      не на экране демо.
- [ ] **Никаких ложных заявлений про оплату/доставку** на публичном демо — модель
      честно помечена как ручная.
- [ ] **Деплой в этом этапе НЕ выполняется** — это будущий этап за чек-листом
      готовности (см. трек деплоя в [`../SALE_READY_MVP_ROADMAP.md`](../SALE_READY_MVP_ROADMAP.md), §5.I)
      и **явным согласием владельца**.

> Инструкции по реальному деплою здесь **намеренно не приводятся** — чтобы исключить
> небезопасные шаги и утечку секретов.
>
> Для **короткого контролируемого** демо по временной ссылке (туннель, только витрина,
> админка остаётся локальной) — безопасный раннбук:
> [`LOCAL_TUNNEL_DEMO_RUNBOOK.md`](./LOCAL_TUNNEL_DEMO_RUNBOOK.md). Сам туннель **не
> создаётся** этим документом и требует отдельного явного согласия владельца. Общий
> аудит готовности — [`LIVE_DEMO_DEPLOY_READINESS.md`](./LIVE_DEMO_DEPLOY_READINESS.md).

## 7. Типовые проблемы на демо / траблшутинг

Основано на известном поведении проекта:

- **БД на 6700 «не сразу готова» после простоя/перезагрузки.** Скрипт `db:start`
  может **ложно завершиться по таймауту**, пока PostgreSQL делает crash-recovery
  fsync, — а сервер при этом поднимается. **Не сбрасывайте БД.** Проверьте
  `npm run db:status` и `npm run db:health`; если показывают `OK`/`running` — всё в
  порядке, продолжайте.
- **`db:start` завис по таймауту** → сначала `db:health` / `db:status`, а не
  пересоздание. Восстановление демо **никогда** не делается через `reset` / `drop`
  / `seed`-перезапись.
- **Админ-маршруты ведут на логин.** Без сессии `/admin/*` отдаёт `307 →
  /admin/login` — это ожидаемо; войдите под dev-учёткой (значения не показывать).
- **Скриншоты корзины/чекаута/админки требуют живой сессии.** Они зависят от
  `localStorage`/авторизации, поэтому простым «URL → скриншот» не снимаются — см.
  ручной чек-лист в [`DEMO_SCREENSHOT_CHECKLIST.md`](./DEMO_SCREENSHOT_CHECKLIST.md).
- **Если что-то не запускается вживую** — показывайте из
  [`screenshots/`](./screenshots/) и ведите рассказ по сценарию.

## 8. Чего НЕ обещать

Повтор честных границ (подробно — [`FEATURES_AND_LIMITS.md`](./FEATURES_AND_LIMITS.md)):

- ❌ **Реального платёжного провайдера** (LiqPay / Fondy / WayForPay / эквайринг) —
  оплата пока **ручная**.
- ❌ **API перевозчика и трекинг** (Новая Почта / Укрпочта) — доставка пока выбор
  способа + текстовая заметка, без API и модели адреса.
- ❌ **Уведомлений** (email / SMS) — их нет.
- ❌ **E-mail-функций кабинета** (сброс/подтверждение пароля) и уведомлений. Сам
  **личный кабинет уже есть** (регистрация/вход, профиль, смена пароля, история
  заказов и страница своего заказа — этапы 47A–47C); **гостевое оформление сохранено**.
- ❌ **Фискализации / РРО / ПРРО, чеков, юридического соответствия** — отдельный
  вопрос к юристу/провайдеру.
- ❌ **Продакшн-деплоя** — живого размещённого магазина пока нет; деплой — будущий
  этап за согласием владельца.
