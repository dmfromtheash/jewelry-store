# AURELIA — Сценарий демонстрации для покупателя (Buyer Demo Script v1)

> **Назначение.** Готовый сценарий на 10–15 минут, чтобы показать AURELIA
> потенциальному покупателю как **готовый брендируемый интернет-магазин**
> украинской бижутерии / аксессуаров / подарков. Документ описывает, что
> показывать, в каком порядке и что **нельзя обещать**.
>
> **Это не маркетинговый питч и не обещание «живого» магазина.** AURELIA —
> sale-ready MVP: *показуемый и адаптируемый*, а не *запущенный и принимающий
> деньги через провайдера*. Все ограничения — в [`FEATURES_AND_LIMITS.md`](./FEATURES_AND_LIMITS.md).
>
> Операционный «день-икс» порядок (запуск, проверки, траблшутинг, готовность
> демо-URL) — в [`DEMO_RUNBOOK.md`](./DEMO_RUNBOOK.md).

---

## 0. Перед показом (1 минута, без покупателя)

- Поднять локальную БД AURELIA: `npm run db:start` (порт **6700**, изолированная;
  Б**dm-bot на 5432 не трогаем**). Проверка: `npm run db:health` → `HEALTH: OK`.
- Запустить витрину: `npm run dev` → `http://127.0.0.1:5000`.
- Войти в админку заранее в отдельной вкладке: `/admin/login`
  (доступ настраивается через переменные окружения — см.
  [`SETUP_AND_HANDOFF_CHECKLIST.md`](./SETUP_AND_HANDOFF_CHECKLIST.md);
  **секреты не показывать на экране**).
- Открыть демо лучше с телефона **и** ноутбука — первое впечатление покупатель
  составляет на телефоне.

> Опционально перед важным показом: `npm run build` и набор `db:verify:*`
> (см. этап 31A) — чтобы убедиться, что сборка и данные в порядке.

## 1. Часть «Покупатель» (≈ 6–8 минут)

**Цель:** показать, что клиент может пройти весь путь от витрины до подтверждённого
заказа — без ручной переписки в директе.

1. **Главная.** Открыть `/`. Показать витрину: категории, карточки товаров,
   баннеры. Подчеркнуть: каталог берётся **из PostgreSQL**, а не захардкожен.
2. **Категория.** Перейти в `/category/bijouterie` (бижутерия) и `/category/gifts`
   (подарки). Показать, что категорий и товаров может быть сколько угодно — это
   **данные**, а не правка кода.
3. **Карточка товара с вариантами.** Открыть **«Серьги “Капля”»**
   (`/product/serogi-kaplya`). Показать:
   - галерею изображений товара;
   - **селектор варианта** (покрытие: позолота / родирование / …) — реальный
     интерактивный выбор;
   - что выбранный вариант **меняет цену** (если у варианта задана надбавка);
   - цена отображается в **₴ (UAH)**.
4. **Добавление в корзину.** Выбрать вариант → «Добавить в корзину». Показать, что
   строка в корзине помечена выбранным вариантом.
5. **Товар без вариантов.** Открыть **«Подарочный сертификат»**
   (`/product/sertifikat-podarochnyj`) — добавляется в корзину как обычно, без
   селектора. Показать, что обе модели уживаются.
6. **Товар «Скоро».** Открыть **«Кулон “Грань”»** (`/product/kulon-gran`,
   статус `coming_soon`) — у него **нет кнопки заказа** и нет цены. Это честный
   приём: недоступный товар нельзя купить.
7. **Корзина.** Открыть корзину: разные варианты одного товара — **отдельные
   строки** (идентичность `slug + variantId`). Кратко упомянуть: скрытые /
   недоступные / распроданные позиции корзину не ломают — уходят в блок
   «недоступно».
8. **Оформление.** Перейти в `/checkout`. Показать честную **ручную** модель:
   - **доставка:** Самовывоз / Новая Почта / Укрпочта / Курьер + свободное поле
     (отделение, адрес, комментарий);
   - **оплата:** «Оплата при получении» **или** «Онлайн-оплата по реквизитам»
     (подтверждается вручную).
   Заполнить имя/телефон/город, оформить заказ.
9. **Подтверждение.** Показать **инлайн-подтверждение** заказа (номер вида
   `AUR-XXXXXXXX`) и что корзина очистилась.

> **Ключевая мысль для покупателя:** «Клиент сам собирает заказ на сайте,
> выбирает доставку и способ оплаты, получает номер заказа — а вы видите этот
> заказ в админке. Оплата и доставка сейчас оформляются **вручную** — это
> сознательная стартовая модель, а не недоделка.»

## 2. Часть «Админ / владелец магазина» (≈ 4–6 минут)

**Цель:** показать, что владелец может реально вести магазин из админки.

1. **Заказы — входящие.** Открыть `/admin/orders`. Показать, что только что
   оформленный заказ появился в списке.
2. **Детали заказа.** Открыть заказ. Показать снимок (snapshot) заказа:
   позиции, **выбранный вариант**, цена на момент заказа, выбранные **способ
   оплаты и доставки**, контактные данные, итог в ₴.
3. **Жизненный цикл заказа.** Провести заказ по статусам:
   `submitted → processing → completed` (или `cancelled`). Подчеркнуть: переходы
   **контролируются** (нельзя «перепрыгнуть» или воскресить завершённый заказ),
   каждый переход — ручное действие админа и попадает в журнал.
4. **Возврат остатка при отмене.** На *тестовом* заказе показать, что **отмена
   возвращает остаток** на склад (для товаров/вариантов, где учёт включён).
5. **Каталог.** Открыть `/admin/catalog`. Показать:
   - создание / редактирование товара (поля, цена, статус);
   - **публикацию / скрытие** товара (скрытый не виден на витрине и его нельзя
     заказать);
   - управление **главным изображением и галереей**;
   - управление **вариантами** (добавить / изменить / удалить, вариант
     «по умолчанию»);
   - **остаток на складе** (на уровне товара и вариантов).

> **Ключевая мысль для покупателя:** «Вы управляете каталогом, фото, вариантами,
> остатками и заказами из админки сами — без программиста для повседневных
> операций.»

## 4. Что НЕЛЬЗЯ обещать на демо

Чтобы не вводить покупателя в заблуждение, **не утверждать**, что:

- ❌ подключён **реальный платёжный провайдер** (LiqPay / Fondy / WayForPay /
  банковский эквайринг). Оплата сейчас **ручная**.
- ❌ есть **интеграция с перевозчиком** (Новая Почта / Укрпочта API): трекинг,
  расчёт стоимости, печать накладных. Доставка сейчас — это **выбор способа +
  текстовая заметка**, без API и без модели адреса.
- ❌ есть **email/SMS-уведомления** покупателю или админу. Их нет.
- ❌ есть **сброс/подтверждение пароля по e-mail** или **уведомления** в кабинете.
  Сам **личный кабинет уже есть** (регистрация/вход, профиль, смена пароля, история
  заказов и страница своего заказа — этапы 47A–47C), и **гостевое оформление
  сохранено**; но e-mail-функции кабинета пока не подключены.
- ❌ есть **фискализация / РРО / ПРРО**, чеки, юридическое соответствие. Это
  отдельный вопрос к юристу/провайдеру, **в продукт не входит**.
- ❌ магазин **развёрнут в проде** и принимает реальные деньги. Демо — локальное
  (или на тестовом стенде); продакшн-деплой — отдельный платный этап.
- ❌ есть готовая **мультиязычность (uk-UA / EN)**. Интерфейс сейчас на русском;
  локализация — будущая опция. EUR/USD — экспортно-готовое будущее, не путь
  оплаты v1.

> Если покупатель спрашивает про что-то из списка выше — отвечать честно: «это
> следующий, отдельно оплачиваемый этап интеграции» и показывать
> [`FEATURES_AND_LIMITS.md`](./FEATURES_AND_LIMITS.md).
