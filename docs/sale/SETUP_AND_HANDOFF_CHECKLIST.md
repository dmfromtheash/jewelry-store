# AURELIA — Чек-лист адаптации и передачи (Setup & Handoff v1)

> **Назначение.** Что нужно поменять, чтобы превратить демо AURELIA в магазин
> конкретного покупателя. Список практический: бренд → каталог → контакты →
> (опционально) провайдеры → деплой.
>
> Оглавление всего пакета продажи (с чего начать, какие скриншоты есть, что
> сделано/не сделано) — [`README.md`](./README.md).
>
> **Безопасность документа:** здесь **нет секретов**, **нет реальных значений
> ключей** и **нет разрушительных команд** (никаких reset / drop / seed-перезаписи).
> Любые значения вроде паролей и секретов задаются покупателем в **`.env.local`**,
> который **никогда не коммитится**.

---

## 1. Бренд: название, логотип, тексты

- [ ] Название магазина и тон текстов (сейчас демо-бренд — **AURELIA**).
- [ ] Логотип и фавикон.
- [ ] Тексты главной, баннеров, информационных страниц (доставка, возврат,
      контакты, помощь, о магазине).
- [ ] Цвета/типографика — **только по отдельному согласованию** (одобренный
      дизайн витрины и карточек по умолчанию не меняется).

## 2. Каталог: товары и фото

- [ ] Заменить демо-каталог (10 посевных товаров) на реальные позиции бренда.
- [ ] Категории под ассортимент покупателя (добавление категорий — это **данные**,
      не код).
- [ ] **Реальные фото** товаров (главное изображение + галерея). Использовать
      только лицензионные/собственные изображения.
- [ ] Варианты (например, покрытие/размер), их надбавки к цене и SKU.
- [ ] Стартовые **остатки** на складе по товарам/вариантам.
- [ ] Статусы (`available` / `coming_soon`) и публикация/скрытие.

## 3. Оплата (ручная модель v1)

- [ ] Описать реквизиты/правила ручной оплаты в текстах чекаута и
      информационных страниц (что значит «онлайн-оплата по реквизитам» и «оплата
      при получении» для конкретного продавца).
- [ ] Решение о **реальном платёжном провайдере** — отдельный будущий этап
      (LiqPay / WayForPay / эквайринг; Fondy по текущим официальным условиям
      онбордит только юрлица UK/EU и не подходит украинскому продавцу), требует
      решения по юрлицу и **актуальной официальной проверки**. См.
      [`PAYMENT_DELIVERY_PROVIDER_RESEARCH.md`](./PAYMENT_DELIVERY_PROVIDER_RESEARCH.md)
      (Украина, сверка официальных источников 2026-06-19), `docs/PAYMENTS_SPEC.md`,
      `docs/PAYMENT_PROVIDER_DECISION.md`.

## 4. Доставка (ручная модель v1)

- [ ] Настроить тексты способов доставки под продавца (Самовывоз / Новая Почта /
      Укрпочта / Курьер) и пояснения к свободному полю (отделение/адрес).
- [ ] **API перевозчика, расчёт стоимости и трекинг** — отдельный будущий этап.
      См. `docs/DELIVERY_SPEC.md`.

## 5. Юридическое и контакты

- [ ] Реальные контакты (телефон, email, мессенджеры, адрес/город).
- [ ] Юридические страницы: оферта, политика возврата, обработка персональных
      данных — **по согласованию с юристом покупателя** (в продукт не входят
      юридические гарантии).
- [ ] **Фискализация (РРО / ПРРО)** и чеки — вопрос к юристу/провайдеру, требует
      **актуальной официальной проверки** до приёма реальных денег.

## 6. Доступ владельца в админку

- [ ] Покупатель задаёт собственные значения переменных окружения в `.env.local`
      (по образцу **`.env.example`**) — **в репозиторий они не попадают**:
  - `ADMIN_USERNAME` — логин администратора;
  - `ADMIN_PASSWORD` — пароль администратора;
  - `ADMIN_SESSION_SECRET` — секрет подписи сессии (длинная случайная строка,
    не короче 32 символов).
- [ ] Вход в админку: `/admin/login`. Админ-маршруты `noindex` и защищены
      локальным гейтом; смена статусов и действия пишутся в журнал (audit log).
- [ ] **Никогда** не коммитить, не пересылать и не показывать на демо реальные
      значения этих переменных.

## 7. База данных (локально / стенд)

- [ ] Локальная БД AURELIA — изолированный PostgreSQL на порту **6700**
      (управление: `npm run db:start` / `db:status` / `db:health`).
- [ ] **Не трогать** постороннюю БД dm-bot на порту **5432** — это отдельная
      система.
- [ ] Подключение задаётся через переменные окружения в `.env.local` (без
      секретов в репозитории).
- [ ] Бэкап перед серьёзными изменениями данных: `npm run db:backup`.
      *(Этот чек-лист сознательно не содержит команд reset/drop/seed-перезаписи —
      они разрушительны и выполняются только владельцем осознанно.)*

## 8. Домен / хостинг / деплой (позже)

- [ ] Продакшн-деплой — **отдельный** этап за чек-листом готовности и **явным
      согласием владельца** (домен, хостинг, секреты окружения, `noindex` снять
      только для витрины, бэкапы, обработка ошибок). См. трек готовности к
      деплою в роадмапе.

## 9. Проверка перед передачей

- [ ] `npm run build` — сборка проходит.
- [ ] `npm run typecheck` — типы в порядке.
- [ ] `npm run db:health` — каталог на месте (`HEALTH: OK`).
- [ ] Набор `db:verify:*` — проверки данных проходят (см. этап 31A).
- [ ] В репозитории **нет секретов**; история коммитов чистая (one stage = one
      commit).
